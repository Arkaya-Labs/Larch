# m13: drafting with the model's own MTP block, 28 Nov 2026 (D0 gate)

Test machine: RTX 5070 Ti 16 GB (sm_120), Ryzen 7 9800X3D, Windows 11 + WSL2 (8 logical CPUs in WSL). Model m13
(`bench/models.toml`). Raw results: [`35b-mtp-draft-2026-11-28/`](35b-mtp-draft-2026-11-28/). Follows
[`35b-moe-kernel-2026-11-28.md`](35b-moe-kernel-2026-11-28.md), whose head (`1136c22`) this branch starts from.

## Summary

**NO-GO at D0; nothing changed in the engine.** Drafting with m13's MTP block (`LARCH_DRAFTER=mtp`) is exact: on
every task set, at forced K = 1 to 4, the drafted tokens equal the same load's plain greedy decode on 12 of 12 prompts.
It does not pay on this card:

- **Measured.** A B B A slices at W4@1, with B the same binary and `LARCH_DRAFTER=mtp`: **−4.6 %** (162.3 against
  170.2 tok/s), TTFT p50 +8.0 %, TPOT p99 +17.0 %.
- **Predicted.** From D0's serve-bench costs: the median task's best gain is 1.011 (W4@1 172.5 → 174.3, +1.1 %),
  against the gate's +10 %.

The drafter's device bytes do two things:

- **Every step is slower.** The MTP block is 898 MB, 855 MB of it Q8_0 routed experts. With the token embedding on the
  device (219 MB) and five check spares (322 MB), the plan splits 25 layers where A splits 15. A plain 1-row step takes
  5.87 ms against 5.28.
- **Seats.** The drafting plan holds **1 state slot**, where A holds 4.

A check row of one sequence then adds 2.07 ms. A guess costs 1.42 ms to propose: the block 0.70 ms, the head
0.56 ms (40 %), argmax and syncs the rest. An observe costs about 0.7 ms.

Even with no drafter bytes at all and an FR-Spec head, the bound is +13.4 % for the median task and +11.0 % on W4's
own prompts. D1's reachable cuts cannot close the gap:

- **Cuts a and b.** Spares sized to K, and the FR-Spec head, give about +9 to +10 % for the median task and +7 % on W4,
  and still leave the 1-slot plan, which the decided rule forbids the default to take.
- **Cut c.** The block split like a trunk layer needs the block's routes recorded and the planner and loader to split
  it, which did not fit the D1 budget.

So no D1, no re-gate, no default. F0 (owed by the kernel pass) found no kernel bug.

The prompt rows of split layers depend on placement, which #21's debt table already lists. Because of it, any load
whose split differs from A's gives other bytes at near ties (margins at most 0.34 logit), drafting on or off. A
drafting load's plain decode therefore differs from A's while its drafted output equals its own plain decode. This
is the reason E, as written ("drafting on vs A"), could not pass on any load whose plan differs from A's.

#21 is not merged, so no pull request is opened; the commands that open the default and kernel passes' pull request
close this report.

## Method

- Every GPU job in one `flock` hold. Before each: no build, `tmux ls` (one session), used VRAM under 2.5 GB, the core
  under 85 C. Builds under `nice -n 19`; no build, test or review during a timed run. Every larch run is on the
  fresh-install protocol (no `LARCH_EXPERT_CACHE`, no `.experts` beside the model before or after; 0 found after each).
  A B run counts only with one `larch_expert_cache_plan` line and `larch_split_decode,mapped=1` (holds: `holds.log`).
- Serve runs: `larch bench -m m13.gguf --mode serve --concurrency <c> --set max_context=2560 --machine wsl5070
  --slice <s>` with `LARCH_FIT_DIAGNOSTICS=1 LARCH_PROFILE_STEPS=1 LARCH_GRAPH_DIAGNOSTICS=1`, as the kernel pass. B
  adds `LARCH_DRAFTER=mtp`; the D0 cost runs use the instrumentation build with `LARCH_D0_FORCE=<K> LARCH_D0_DPROF=1`.
  A B B A noise rule: under 2 % or under either side's spread.
- tokdump runs: `tokdump <m13.gguf> <prompts.jsonl> <out.jsonl> 256 <chats>` (context 2560, greedy, top-2 logprobs,
  no prefix cache, think blocks kept in the output). Built with `cargo build --release --locked -p larch
  --no-default-features --example tokdump` at each commit (F0: `2e456f5` in a detached worktree, sha256 `deddd276…`;
  `1136c22`, `87bf5945…`).
- Gain: `tools/gain.py costs-serve.json <task>=a1,a2,a3,a4 …`. Divergence: `tools/cmp.py`.
