### Commands

Each window: `flock -w 14400 ~/src/gpu.lock timeout 3600 <script>`. Inside it, per server: start, `timeout 900`
health wait, the bench's warm-up, rows, kill, nvidia-smi until the memory is back. Order: AWQ r1, larch r1, AWQ r2,
larch r2, GGUF r1, then the control. No vLLM process runs during a larch window.

Server (environment `HF_HUB_OFFLINE=1 HF_HUB_DISABLE_IMPLICIT_TOKEN=1 TORCHINDUCTOR_COMPILE_THREADS=4`, the last for
compile-time memory only):

```
vllm serve <awq> --port 8000 --max-model-len 8192 --seed 0 --enable-prompt-tokens-details --gpu-memory-utilization 0.90 [--no-enable-prefix-caching]
vllm serve <models>/m1.gguf --tokenizer <awq> --port 8000 --max-model-len 8192 --seed 0 --enable-prompt-tokens-details --gpu-memory-utilization 0.90 [--no-enable-prefix-caching]
```

W1 and W2 run with prefix caching on (the default), on a fresh server for each of W1, W2 at 4 and W2 at 8: a server
keeps its prefix cache between runs. W4 runs on one server with `--no-enable-prefix-caching` for all four
concurrencies.

Client and larch:

```
larch bench -m <models>/m1.gguf --engine openai --url http://127.0.0.1:8000 --machine wsl5070 --workload chat --concurrency 1 --json <out>
larch bench -m <models>/m1.gguf --engine openai --url http://127.0.0.1:8000 --machine wsl5070 --workload chats --concurrency 4 --json <out>   # then 8, own server
larch bench -m <models>/m1.gguf --engine openai --url http://127.0.0.1:8000 --machine wsl5070 --mode serve --concurrency 1,4,8,16 --json <out>
larch bench -m <models>/m1.gguf --machine wsl5070 --workload chat --concurrency 1 --json <out>
larch bench -m <models>/m1.gguf --machine wsl5070 --workload chats --concurrency 4,8 --json <out>
larch bench -m <models>/m1.gguf --machine wsl5070 --mode serve --concurrency 1,4,8,16 --set max_context=2560 --json <out>
```

## Not like for like

- AWQ INT4 and Q4_K_M are different 4-bit weights; the GGUF row is the same-weights row.
- larch through `larch serve` is not charted: serve has no `ignore_eos`.
- vLLM's `ignore_eos` stops checking end-of-generation tokens but can still sample one and continue; llama.cpp and
  larch mask them, so they never sample one. Answer lengths are equal either way.
- `n_ctx_seq`: vLLM 8192 (its `max_model_len`) on every row; larch 2560 on W4 (the driver's row), 8192 on W1 and W2.
- vLLM's prefix cache is shared across requests in 16-token blocks; larch's W1 and W2 reuse is each conversation's
  own parked KV (counts above).
